## はじめに

社内で、こんな話題が出ました。

> AIに雑に依頼して、結構いい成果物や資料を出させるには？

:::message
私は、雑に頼めるかどうかは頼み方の技術ではなく、**判断基準を先に渡しているかどうか**で決まると考えています。
:::

![同じ雑な依頼でも、判断基準を渡しているかどうかで、道具として使うかエージェントとして任せるかに分かれる](/images/ai-agent-judgment-criteria/fig-fork.png)

私は開発とPjMを兼任していて、コードだけでなく、仕様書づくりや会議の準備もAIに任せています。その考え方と実例を、図で紹介します。

## AIは「知能」

AIは人工知能です。では、知能とは何でしょうか。私は、**状況を把握し、目的に照らして次の行動を判断できること**が知能だと考えています。

![道具は入力に決まった処理を返す。知能は状況を把握し、判断し、行動し、結果を確認して次を選ぶ](/images/ai-agent-judgment-criteria/fig-intelligence.png)

判断ができるなら、AIには手順ではなく、仕事そのものを任せられると思います。

## 道具として「使う」か、エージェントとして「任せる」か

この二つの違いは、判断を誰が持つかにあると思います。

| | 道具として使う | エージェントとして任せる |
|---|---|---|
| 渡すもの | 手順 | 目的と判断基準 |
| 方針・計画を決めるのは | 人 | AI（私の判断基準で） |
| 人がやること | 一つひとつの指示と確認 | 判断基準を書き、外部に出る操作を承認する |
| 同時に進められる仕事 | 1つ | いくつも |
| 失敗したときに直すもの | その場の指示 | 判断基準（次からすべての仕事に効く） |

同じ仕事、PRのレビュー指摘への対応で比べます。

![PRのレビュー指摘への対応。道具として使うと人の作業は4回かける指摘の数、任せると人の出番は頼むときと送信の承認の2回](/images/ai-agent-judgment-criteria/fig-pr-review.png)

## 任せると失敗する理由

AIは判断できますが、私の判断基準までは知りません。任せて失敗する原因の多くは、ここにあると見ています。実際にあった失敗です。

| AIがしたこと | 一般論としては | 私の判断基準 |
|---|---|---|
| 処理を確実にするため、設計にない管理用テーブルを追加した | 確実にするのは良いこと | 便利さや確実さを理由に、設計にないものを足さない |
| 打ち合わせの確認シートに、決まっていることまで質問として並べた | 確認は多いほど安全 | 決まっていることは聞かない（18問 → 5問） |
| 合意の記録が見つからないので、確認依頼の文面を作った | 記録がなければ確認する | 合意の記録がないことだけを理由に、確認依頼を作らない |
| リリース時の動作確認を、途中の画面で止める手順にした | 余計なデータを増やさない | 動作確認は、利用者の操作が最後まで終わるところまで |
| 詳しく、長い文書を書いた | 詳しいほど親切 | 読む人が聞き返さずに判断できる分だけ書く |

どれも、一般論としては間違っていないと思います。ずれていたのは判断基準でした。

![その場の指示を直しても効くのは今の仕事だけ。判断基準に1行足すと次からのすべての仕事に効く](/images/ai-agent-judgment-criteria/fig-fix-scope.png)

## 判断基準を文書にする

私は、書くべきなのはその場の指示ではなく、**迷ったときに何を優先するか**だと考えています。

| その場の指示（その仕事にだけ効く） | 判断基準（迷ったときに効く） |
|---|---|
| 「このヘルパー関数は作らないで」 | 1行の処理を薄いラッパーに切り出さない。同じ変換が2か所以上で重複したら共通化する |
| 「ここは既存の書き方に合わせて」 | 新しい仕組みを作る前に、同じプロジェクトの既存の実装を探して、その方式を使う |
| 「最初からやり直さないで」 | 中断した作業は、最初からやり直さず、止まった地点から続ける |

実際のファイルの一部です。

```markdown:writing-style.md（日本語に訳して抜粋）
## 要点だけ書く
1. 結論・依頼・影響・期限・判断すべきことを残し、それ以外は消す。
2. 同じ種類の文書は、同じ形式で書く。
3. 自明なことは書かない。
4. 判断を変えない細かい例外は書かない。
5. 実際に動く人が、聞き返さずに判断・作業できるように書く。

判断基準：この1文を消したら、読む人の判断や行動が変わるか。
変わらないなら消す。
```

置き場所は、効く範囲で分けています（Claude Code の場合）。

![指摘や失敗は、効く範囲によって、常に読む規則、作業ごとのスキル、プロジェクトのメモリのどれかに記録する](/images/ai-agent-judgment-criteria/fig-where.png)

## 任せると、同時に進められる

私は、判断までAIに任せるほど、人を待たずに進む仕事が増え、同時にいくつも動くようになると考えています。任せたときの1日の動き方です。

![任せた1日の動き。要件の整理から仕様書の作成までをAIが進め、人は頼むとき、外部への送信を承認するとき、判断基準を直すときに関わる](/images/ai-agent-judgment-criteria/day-delegated.png)

任せる範囲を広げるほど、私が1回話しかけるあいだにAIが進める作業は増えていくと思います。

![任せる範囲を広げるほど、発言1回あたりにAIが進める作業は増え、仕事を分けて並列にすると大きく増える](/images/ai-agent-judgment-criteria/delegation-stages.png)

## おわりに

| | 今できていること | これから |
|---|---|---|
| 判断基準 | 私個人の価値観と学び | チームで共有する判断基準 |
| AIが読める情報 | 私が扱う文書とツール | チームの資料とデータ |
| 人の役割 | 判断基準を書き、外部に出る操作を承認する | 判断基準をチームで育てる |

取り消せない操作や外部への送信は、今はまだ私が承認しています。こちらは当面、人間に残る仕事だと考えています。

個人では、ここまでできるようになりました。次は、これをチームの単位に広げたいと思っています。

AIを道具として使うか、任せる相手として扱うか。まずは、自分の判断基準を1行書くところから始めてみてはいかがでしょうか。
